# 데이온 DAYON · 우리 팀의 하루

직원 4명이 같은 업무·일정·입고·택배 발송을 보고 채팅하는 웹앱입니다. 하나의 Node.js 서버와 SQLite 데이터베이스를 사용하므로 별도 Supabase 계정이나 API 키 없이 실행할 수 있습니다.

## 실행과 첫 관리자 생성

Node.js **24 이상**이 필요합니다. 외부 패키지 설치나 빌드는 필요 없습니다.

```sh
cd /workspace/123
npm start
```

기본 포트는 `3000`입니다. 실행 중인 서버에 브라우저로 접속하면 최초 관리자 설정 화면이 표시됩니다.

1. 서버가 처음 생성한 `data/setup-token` 파일의 초기 설정 키를 서버 관리자가 직접 확인합니다. 키는 채팅이나 저장소에 올리지 마세요. 환경변수 `MOA_SETUP_TOKEN`으로 별도 지정할 수도 있습니다.
2. 화면에 설정 키, 관리자 이름, 로그인 아이디, 10자 이상의 비밀번호를 입력합니다. 관리자 생성은 한 번만 가능합니다.
3. **팀 관리 → 직원 초대**에서 이름과 아이디를 정하고 초대 링크를 복사해 직원에게 직접 전달합니다.
4. 직원은 자신의 브라우저에서 링크를 열고 비밀번호를 설정합니다. 초대는 24시간 유효하며 한 번만 사용됩니다. 대기 중인 초대를 포함해 최대 4명입니다.

초대 코드는 브라우저 주소의 fragment로 전달되며 앱이 읽은 뒤 주소에서 지웁니다. 서버에는 코드의 해시만 저장됩니다. 관리자는 대기 중인 초대를 취소하고 다시 만들 수 있습니다.

처음에는 업무와 일정이 비어 있습니다. 이전 체험 버전의 브라우저 로컬 데이터는 자동으로 이전하거나 삭제하지 않습니다.

## 사용할 수 있는 기능

- 로그인한 직원 이름과 실제 팀원 목록
- 오늘의 업무·입고·발송 현황
- 전체 업무, 내 담당 업무, 내가 요청한 업무
- 공용 월간 달력 / 표 보기 및 유형 필터
- 담당자 지정, 일정 등록·수정·완료·취소
- 입고 완료 수량 누적 및 완료 취소 시 반영 취소
- 택배 발송 일정·메모·택배사/운송장 기록
- 팀 전체 채팅 및 업무·일정 변경 실시간 동기화
- 서버 연결 상태와 자동 재연결, 작성 중 채팅 내용 유지
- 모바일 반응형 화면

같은 서버에 접속한 직원들이 같은 데이터베이스를 사용합니다. 데이터는 서버의 `data/moa.sqlite`에 저장되며 서버나 브라우저를 재시작해도 유지됩니다. 다른 직원이 먼저 수정한 일정을 덮어쓰려 하면 최신 내용을 확인하도록 안내합니다. 완료된 입고를 다시 완료해 재고를 중복 반영하는 것도 막습니다.

## 접근 권한과 데이터 범위

로그인한 팀원 모두가 공용 업무·일정·메모·발송 정보를 보고 수정할 수 있습니다. 직원 초대와 초대 취소는 관리자만 가능합니다. 비밀번호는 scrypt 해시, 로그인 세션과 초대 코드는 해시로 저장합니다. 로그인은 HttpOnly 세션 쿠키를 사용하고, 쓰기 요청에 CSRF 및 요청 출처 검사를 적용합니다. 로그인 상태는 7일 동안 유지됩니다. 로그인·가입·초기 설정 요청은 IP당 15분에 30회로 제한됩니다.

로그인 화면, JavaScript, CSS는 공개되지만 실제 직원·업무·채팅 데이터 API는 로그인해야 사용할 수 있습니다. DB·설정 키 파일은 웹 경로로 제공하지 않습니다.

## 실행 환경

| 변수 | 기본값 | 용도 |
|---|---|---|
| `PORT` | `3000` | 서버 포트 |
| `HOST` | `0.0.0.0` | 바인딩 주소 |
| `MOA_DATA_DIR` | 저장소의 `data/` | DB와 초기 설정 키 저장 경로 |
| `MOA_SETUP_TOKEN` | 최초 실행 시 자동 생성 | 첫 관리자 생성에 쓰는 설정 키 |
| `MOA_SECURE_COOKIE` | 미설정 | HTTPS 배포 시 `1`로 지정 |

사내망 개발 실행과 외부 공개 배포는 별개입니다. 외부에서 사용하려면 도메인과 HTTPS, 지속적으로 실행할 서버, 영구 데이터 볼륨을 준비해야 합니다. HTTPS 프록시는 원래 `Host` 헤더를 보존하고 SSE 응답을 버퍼링하지 않도록 설정하세요. HTTPS 운영 환경에서는 `MOA_SECURE_COOKIE=1`을 사용합니다. Node 프로세스는 한 개로 실행합니다.

`data/` 전체는 Git에서 제외됩니다. 서버를 중지한 뒤 데이터 디렉터리를 접근이 제한된 다른 위치에 복사해 백업할 수 있습니다. 실행 중인 SQLite의 `.sqlite` 파일만 복사하면 WAL에 있는 최근 변경을 놓칠 수 있습니다. 복원 시에는 서버를 중지하고, 백업을 별도의 데이터 디렉터리에 복사한 뒤 `MOA_DATA_DIR`로 지정하면 기존 데이터를 보존하면서 복원본을 실행할 수 있습니다. 자동 백업과 계정 비밀번호 재설정은 아직 제공하지 않습니다.

## 검증

```sh
npm run check
npm test
```

Node의 기본 테스트 러너로 임시 DB와 서버를 생성합니다. 최초 설정 보호, 로그인/CSRF/로그아웃, 권한, 초대 정원·재사용 방지, 실제 두 세션 간 데이터 공유, 동시 완료 충돌, 재고 반영, SSE 알림 및 연결 종료, 서버 재시작 후 데이터 보존을 검증합니다. 운영 데이터는 사용하지 않습니다.

실제 Chromium의 분리된 두 브라우저 세션에서도 관리자 생성 → 초대 가입 → 업무 배정 → 입고 완료/취소 → 양방향 채팅 → 새로고침 및 로그아웃 흐름과 모바일 화면을 검증했습니다.

## 현재 범위

실시간 채팅은 팀 전체방 하나이며 최근 500개 메시지를 표시합니다. 개인 대화, 파일 첨부, 읽음 표시, 푸시 알림, PWA 설치는 아직 제공하지 않습니다. 재고는 입고 일정 제목별 완료 수량의 누적이며 별도 SKU·실사·부분 입고·발송에 따른 자동 차감은 없습니다. 택배사 자동 접수와 송장 출력도 아직 연결하지 않았습니다. 모든 팀원이 모든 업무를 함께 보는 방식이며 배송지에 대한 별도 담당자 제한은 없습니다.

무료 기본 주소를 사용하는 배포 준비와 계정 연결 절차는 [배포 안내](deploy/README.md)를 참고하세요. 검토용 Render 설정 초안도 포함되어 있습니다. 외부 공개 배포, 실제 주소 발급 및 새 서버에서의 복원 검증은 아직 하지 않았습니다.
