# 데이온 DAYON · 우리 팀의 하루

직원 4명이 같은 업무·일정·입고·택배 발송을 보고 채팅하는 웹앱입니다. 로컬 개발은 Node.js와 SQLite로 실행하고, 무료 웹 서버에 배포할 때는 별도 PostgreSQL 데이터베이스에 업무 기록을 저장할 수 있습니다.

무료 시험 운영은 **Render Free + Neon Free + Render 기본 주소** 구성으로 준비했습니다. 가입·연결 순서는 [배포 안내](deploy/README.md)를 참고하세요. 아직 공개 배포나 실제 주소 발급은 하지 않았습니다.

## 로컬 실행과 첫 계정 생성

Node.js **24 이상**이 필요합니다. 잠금 파일에 맞춰 의존성을 설치합니다.

```sh
cd /workspace/123
npm ci
npm start
```

`DATABASE_URL`을 지정하지 않는 로컬 실행에서는 기본적으로 SQLite를 사용합니다. 기본 포트는 `3000`입니다.

1. 서버가 처음 생성한 `data/setup-token` 파일의 초기 설정 키를 서버 관리자가 직접 확인합니다. 키를 채팅이나 저장소에 올리지 마세요. 환경변수 `MOA_SETUP_TOKEN`으로 별도 지정할 수도 있습니다.
2. 화면에 설정 키, 이름, 로그인 아이디, 10자 이상의 비밀번호를 입력합니다. 첫 계정 생성은 한 번만 가능합니다.
3. **사용자 → 직원 초대**에서 이름과 아이디를 정하고 초대 링크를 복사해 직원에게 직접 전달합니다.
4. 직원은 자신의 브라우저에서 링크를 열고 비밀번호를 설정합니다. 초대는 24시간 유효하며 한 번만 사용됩니다. 대기 중인 초대를 포함해 최대 4명입니다.

초대 코드는 브라우저 주소의 fragment로 전달되며 앱이 읽은 뒤 주소에서 지웁니다. 서버에는 코드의 해시만 저장됩니다. 총괄과 공동관리자는 대기 중인 초대를 취소하고 다시 만들 수 있습니다.

처음에는 업무와 일정이 비어 있습니다. 이전 체험 버전의 브라우저 로컬 데이터나 SQLite 기록은 PostgreSQL로 자동 이전하지 않습니다. 기존 파일을 자동으로 삭제하지도 않습니다.

## 사용할 수 있는 기능

- 로그인한 직원 이름과 실제 팀원 목록
- 오늘의 업무·입고·발송 현황
- 전체 업무, 내 담당 업무, 내가 요청한 업무
- 공용 월간 달력 / 표 보기 및 유형 필터
- 담당자 지정, 일정 등록·수정·완료·취소
- 입고 완료 수량 누적 및 완료 취소 시 반영 취소
- 택배 발송 일정·메모·택배사/운송장 기록
- 공용 채팅 및 업무·일정 변경 실시간 동기화
- 서버 연결 상태와 자동 재연결, 작성 중 채팅 내용 유지
- 모바일 반응형 화면

같은 서버에 접속한 직원들이 같은 데이터베이스를 사용합니다. 다른 직원이 먼저 수정한 일정을 덮어쓰려 하면 최신 내용을 확인하도록 안내합니다. 완료된 입고를 다시 완료해 재고를 중복 반영하는 것도 막습니다.

## 저장 방식

| 구성 | 저장 위치 | 필요한 설정 |
|---|---|---|
| 로컬 개발 | `data/moa.sqlite` | 기본 설정 |
| 무료 웹 서버 | 외부 PostgreSQL | `DATABASE_URL`, 초기 `MOA_SETUP_TOKEN` |

`DATABASE_URL`을 지정하면 사용자, 세션, 초대, 업무, 재고에 사용하는 입고 기록, 채팅을 PostgreSQL에 저장합니다. 외부 DB 연결에 실패했다고 SQLite로 자동 전환하지 않습니다. 무료 배포 예제는 `MOA_REQUIRE_DATABASE_URL=1`로 접속 주소 누락도 시작 단계에서 막습니다. DB에 아무 사용자도 없는 첫 실행에서는 명시적으로 지정한 `MOA_SETUP_TOKEN`이 필요합니다. 무료 서버의 임시 디스크에 생성한 키에 의존하지 않습니다.

무료 웹 서버를 재배포해도 같은 외부 데이터베이스를 계속 연결하면 기록을 유지할 수 있습니다. 데이터베이스 자체의 삭제, 제공자의 무료 보존 조건, 백업 범위는 별도로 확인해야 합니다. 실제 Neon 계정에서의 배포·재배포 검증은 아직 하지 않았습니다.

## 접근 권한과 데이터 범위

로그인한 팀원 모두가 공용 업무·일정·메모·발송 정보를 보고 수정할 수 있습니다. 총괄과 공동관리자는 직원 초대와 초대 취소를 할 수 있으며, 매뉴얼 작성·수정·삭제 및 자료실 업로드·삭제도 동등하게 사용할 수 있습니다. 비밀번호는 scrypt 해시, 로그인 세션과 초대 코드는 해시로 저장합니다. 로그인은 HttpOnly 세션 쿠키를 사용하고, 쓰기 요청에 CSRF 및 요청 출처 검사를 적용합니다. 로그인 상태는 7일 동안 유지됩니다. 로그인·가입·초기 설정 요청은 IP당 15분에 30회로 제한됩니다.

로그인 화면, JavaScript, CSS는 공개되지만 실제 직원·업무·채팅 데이터 API는 로그인해야 사용할 수 있습니다. DB·설정 키 파일은 웹 경로로 제공하지 않습니다. 데이터베이스 연결 주소와 설정 키는 서버의 비밀 환경변수로 관리합니다.

## 실행 환경

| 변수 | 기본값 | 용도 |
|---|---|---|
| `PORT` | `3000` | 서버 포트 |
| `HOST` | `0.0.0.0` | 바인딩 주소 |
| `DATABASE_URL` | 미설정 | 설정하면 PostgreSQL 사용; 비밀 접속 주소 |
| `MOA_REQUIRE_DATABASE_URL` | 미설정 | 무료 웹 배포에서는 `1`; 접속 주소가 없으면 시작 거부 |
| `MOA_DATA_DIR` | 저장소의 `data/` | SQLite 개발 데이터와 초기 설정 키 저장 경로 |
| `MOA_SETUP_TOKEN` | SQLite는 최초 자동 생성 | 첫 계정 생성 키; 외부 DB 첫 실행에는 필수 |
| `MOA_SECURE_COOKIE` | 미설정 | HTTPS 배포 시 `1`로 지정 |

인터넷의 PostgreSQL은 TLS 인증서 검증을 사용합니다. 암호화하지 않는 연결은 루프백 테스트 DB에만 허용합니다. HTTPS 프록시는 원래 `Host` 헤더를 보존하고 SSE 응답을 버퍼링하지 않도록 설정하세요. HTTPS 운영 환경에서는 `MOA_SECURE_COOKIE=1`을 사용하고 Node 프로세스는 한 개로 실행합니다.

## 백업과 유료 전환

SQLite의 `data/` 전체는 Git에서 제외됩니다. 로컬 서버를 중지한 뒤 데이터 디렉터리를 접근이 제한된 다른 위치에 복사해 백업할 수 있습니다. 실행 중인 `.sqlite` 파일만 복사하면 WAL에 있는 최근 변경을 놓칠 수 있습니다. 복원 시 서버를 중지하고 백업을 별도의 디렉터리에 복사한 뒤 `MOA_DATA_DIR`로 지정하면 기존 데이터를 보존하면서 복원본을 실행할 수 있습니다.

PostgreSQL 백업은 연결한 데이터베이스 서비스의 내보내기·백업·복원 범위를 확인해 별도로 준비합니다. 이 앱은 외부 DB의 자동 백업이나 직원 계정 비밀번호 재설정 기능을 제공하지 않습니다.

무료로 사용하다 Render 서버를 유료로 올릴 때 같은 PostgreSQL 데이터베이스와 연결 설정을 유지하면 데이터를 이동할 필요가 없습니다. DB 서비스나 저장 방식을 바꾼다면 백업과 별도 이전이 필요합니다. 자세한 절차는 [배포 안내](deploy/README.md)를 참고하세요.

## 검증

```sh
npm run check
npm test
```

기본 테스트는 임시 SQLite와 서버를 사용하여 초기 설정 보호, 로그인/CSRF/로그아웃, 권한, 초대 정원·재사용 방지, 실제 두 세션 간 데이터 공유, 동시 완료 충돌, 재고 반영, SSE 알림 및 연결 종료, 서버 재시작 후 데이터 보존을 검증합니다. 운영 데이터는 사용하지 않습니다.

실제 PostgreSQL 테스트는 **테스트 전용 데이터베이스**의 접속 주소를 `MOA_TEST_DATABASE_URL` 환경변수에 안전하게 설정한 뒤 실행합니다. 운영 DB 주소를 지정하지 마세요.

```sh
npm run test:postgres
```

이 테스트는 실제 PostgreSQL을 사용합니다. 테스트 코드와 실행 결과를 확인해 SQLite 검증, PostgreSQL 검증, 공개 서비스에서의 검증을 구분하세요. 이전 버전은 실제 Chromium의 분리된 두 브라우저 세션에서도 첫 계정 생성 → 초대 가입 → 업무 배정 → 입고 완료/취소 → 양방향 채팅 → 새로고침 및 로그아웃 흐름과 모바일 화면을 검증했습니다.

## 현재 범위

실시간 채팅은 팀 전체방 하나이며 최근 500개 메시지를 표시합니다. 개인 대화, 파일 첨부, 읽음 표시, 푸시 알림, PWA 설치는 아직 제공하지 않습니다. 재고는 입고 일정 제목별 완료 수량의 누적이며 별도 SKU·실사·부분 입고·발송에 따른 자동 차감은 없습니다. 택배사 자동 접수와 송장 출력도 아직 연결하지 않았습니다. 모든 팀원이 모든 업무를 함께 보는 방식이며 배송지에 대한 별도 담당자 제한은 없습니다.

무료 서비스의 대기 상태, 사용량 한도, 보존·백업 정책은 제공자 조건을 따릅니다. 여기서는 최신 한도 수치나 비용 0의 영구 유지를 보장하지 않습니다. 가입 시 Free 요금제와 최종 금액을 확인하고, 유료 자원 생성은 별도 선택으로 진행합니다.

## 아카이브 · 검색 · 매뉴얼 · 자료실

- **아카이브**는 완료한 업무·입고·발송·공통 일정을 보여줍니다. 제목·메모·운송장 검색, 담당자·구분·업무 예정일 필터 및 50개씩 더 보기를 지원합니다. 완료 취소는 기존 입고 재고에도 반영됩니다. 이전 버전에서 완료한 기록은 완료 시각이 없을 수 있으며 업무 예정일로 찾을 수 있습니다.
- **채팅 검색**은 최근 화면의 500개 제한과 별도로 DB에 남아 있는 전체 대화를 검색합니다. 내용·작성자·한국 시간 기준 기간 필터와 50개씩 더 보기를 지원합니다. 기존 대화를 삭제하지 않습니다.
- **문서**는 **매뉴얼 / 기타** 두 하위 탭에서 글을 작성·수정·삭제하고 읽는 기능입니다. 기존 글은 매뉴얼 탭에 유지되며, 편집 화면의 구분 선택으로 기타 탭으로 옮길 수 있습니다. 기존 업무 메뉴는 별도로 유지합니다. 매뉴얼을 선택하면 팝업 대신 본문 전체가 문서 편집 화면으로 바뀌며 제목·분류·본문을 바로 수정합니다. 문단 왼쪽 **＋**로 바로 아래에 텍스트, 제목 1·2·3, 토글, 글머리·번호 목록, 체크리스트, 인용문, 콜아웃, 구분선, 표를 추가하고, **⠿**로 종류 변경·위아래 이동·복제·삭제하거나 손잡이를 끌어서 순서를 바꿀 수 있습니다. 빈 문단에서 `/`로 종류 메뉴를 열고 Enter로 다음 문단, Shift+Enter로 줄바꿈합니다. 각 문단 왼쪽의 ＋·⠿는 마우스를 올리면 표시됩니다. 터치 기기에서는 바로 사용할 수 있도록 표시합니다. 기존 여러 줄 텍스트와 여러 줄 붙여넣기는 줄별 독립 블록으로 나누며, Shift+Enter는 같은 블록 안의 줄바꿈으로 유지합니다. 토글 내부도 문단별 블록으로 편집하며 제목·다른 토글·표 등을 중첩해서 추가할 수 있습니다. 토글을 일반 문단으로 바꾸면 내부 문단은 바깥으로 옮겨 보존합니다. 표는 행·열 추가와 마지막 행·열 삭제를 지원합니다(최대 30행·10열, 첫 행은 머리글). 읽기 미리보기에서 완성된 문서와 접기·펼치기를 확인할 수 있습니다. 상단 **저장**을 누르면 문서를 유지한 채 저장 상태를 표시하며 **문서 목록**으로 돌아갈 수 있습니다. 저장하지 않은 변경사항이 있으면 다른 메뉴로 이동하거나 창을 닫기 전에 확인합니다. 실시간 데이터 갱신은 편집 중인 문서를 다시 그리지 않습니다. 기존 일반 텍스트 글도 그대로 불러옵니다. 제목·분류·본문 검색을 지원합니다. 동시 수정 시 덮어쓰기를 막습니다.
- **자료실**은 모든 로그인 사용자의 업로드·삭제·검색·다운로드를 지원합니다. 파일당 5MB, 전체 파일의 원본 크기 합계 25MB입니다. PDF·이미지·Office 문서·TXT·CSV·ZIP을 지원하며 다운로드로 제공합니다. 사진을 매뉴얼에 직접 삽입하는 기능은 아직 없습니다.
- 무료 서버의 임시 디스크 대신 선택된 데이터베이스에 자료 파일도 저장합니다. PostgreSQL 배포에서는 서버 재시작·재배포와 독립적으로 유지됩니다. Base64 저장으로 DB의 실제 사용량은 파일 원본보다 약 1/3 늘어나며, 무료 서비스의 전체 저장·전송 한도도 함께 적용됩니다. 영상이나 대용량 파일은 별도 파일 저장소로 전환하는 것이 적합합니다.
- 기존 DB를 지우지 않고 새 테이블과 완료 시각 컬럼을 추가합니다. 적용 전 백업을 권장하며, 운영 서버에 대한 확인은 로그인한 직원 계정으로 별도 진행해야 합니다.

## 동등한 사용자 권한과 디자인

총괄·공동관리자·운영자는 업무와 문서·자료를 함께 관리하며, 직원 초대·초대 취소는 총괄과 공동관리자만 사용할 수 있습니다. 공개 회원가입은 열지 않고 초대 가입과 최초 설정 키, 로그인·CSRF 검사는 유지합니다. 기존 DB의 역할 컬럼은 저장 호환성을 위해 유지하고, 별도의 account_access에 저장한 권한·활성 상태로 계정 관리 접근을 판정합니다. 계정·업무 데이터의 재생성이나 역할 값 변경은 필요하지 않습니다.

화면은 관리자·멤버 표식을 없애고 동일한 크기의 이름과 아바타로 표시합니다. 사용자 목록은 이름순으로 정렬합니다. `팀 채팅`은 `채팅`, `팀 관리`는 `사용자` 메뉴로 변경했습니다. 전체 화면에 시스템 글꼴, 흰색·밝은 회색 표면, 파란색 포인트, 일관된 선 아이콘·라운드 컨트롤을 적용했습니다. PC와 휴대폰에서 동일한 기능을 제공하고 키보드 포커스 및 동작 줄이기 설정을 지원합니다.

## 주간·야간 모드와 해야 할 일 알림

- 로고는 `Dayon`으로 표시합니다. 오른쪽 위 모드 버튼으로 주간·야간 화면을 전환합니다. 로그인 화면에도 같은 버튼이 있으며, 첫 방문에는 기기의 밝기 설정을 따르고 직접 선택하면 이 브라우저에 저장합니다. 다른 기기로 자동 동기화되지는 않습니다.
- 종 모양 **해야 할 일 알림**은 로그인한 사람에게 배정된 미완료 업무·입고·발송·일정 중 오늘 마감 또는 기한이 지난 항목을 표시합니다. 항목을 누르면 상세 내용을 확인할 수 있고 완료하면 목록에서 빠집니다. 날짜 판정은 한국 시간 기준입니다.
- 앱 내 알림은 별도 허용 없이 동작합니다. 종 버튼 안의 **브라우저 알림 → 켜기**를 누를 때만 브라우저의 알림 허용을 요청합니다. 브라우저가 지원하고 허용한 경우 Service Worker 알림으로 마감 건수를 표시합니다. 제목·메모 등 업무 내용은 시스템 알림 본문에 넣지 않습니다.
- 앱이 열린 동안 실시간 변경과 1분 간격으로 알림 대상을 확인합니다. 동일 항목·버전은 이 브라우저에서 하루 한 번 알리고, 수정되거나 다음 날에도 미완료이면 다시 대상이 됩니다. 수신 설정은 로그인한 사람별로 이 브라우저에 저장합니다. OS 설정과 브라우저 정책에 따라 표시·소리는 달라질 수 있습니다.
- **모든 Dayon 창을 완전히 닫은 상태의 예약·푸시 알림은 지원하지 않습니다.** 서버 푸시 구독과 예약 발송 서비스는 이번 변경에 포함하지 않았습니다. 브라우저 알림을 차단해도 앱 안의 할 일 목록은 사용할 수 있습니다.
- 로그아웃하면 화면의 개인 알림 목록과 열린 시스템 알림을 정리합니다. 페이지·업무·로그인 응답을 Service Worker에 캐시하지 않습니다.

## 오른쪽 아래 채팅 위젯

- 로그인하면 어느 메뉴에서든 오른쪽 아래 **채팅** 버튼으로 작은 대화창을 열고 바로 메시지를 보낼 수 있습니다. 위젯은 최근 100개를 보여주고, 위쪽 확장 버튼은 기존 전체 대화·검색 화면으로 연결합니다. Enter로 보내며 Shift+Enter는 줄바꿈입니다. 한글 조합 중 Enter는 전송으로 처리하지 않습니다.
- 다른 사람이 보낸 새 메시지는 위젯이 닫혀 있을 때 **이름·대화 미리보기 알림**과 읽지 않은 개수로 표시합니다. 본인이 보낸 메시지와 첫 로그인 때 이미 있던 대화는 새 메시지 팝업으로 다시 알리지 않습니다. 처음 접속했을 때의 미확인 기록은 개수에는 포함됩니다.
- 읽지 않은 개수는 최근 100개·500개 표시 제한과 별개로 전체 저장 기록에서 셉니다. 읽은 위치는 계정별로 DB에 저장되므로 새로고침·재로그인·다른 기기에서도 공유됩니다. 화면이 실제로 보이고 포커스가 있으며, 위젯이나 전체 채팅의 최신 대화를 확인할 때 읽음 처리합니다. 검색 결과만 보고 있거나 이전 대화를 스크롤하는 중에는 새 대화를 자동으로 읽음 처리하지 않습니다.
- 위젯 아래 **브라우저 알림 켜기**를 누르면 지원되는 브라우저에서 권한을 요청합니다. 선택하면 새 메시지의 보낸 사람·미리보기가 시스템 알림에도 표시됩니다. 할 일 브라우저 알림과는 별도 설정이며, 수신 선택과 시스템 알림 중복 방지 위치는 이 브라우저에 계정별로 저장합니다. 위젯을 켜지 않아도 앱 내 새 메시지 팝업은 표시됩니다.
- **Dayon을 완전히 닫은 상태의 서버 푸시는 제공하지 않습니다.** Dayon 탭이 열려 있고 서버와 연결되어 있어야 새 대화를 실시간 수신합니다. 브라우저 알림을 허용하지 않거나 브라우저가 지원하지 않아도 앱 내 팝업과 읽지 않은 개수는 사용할 수 있습니다.
- 읽음 처리 API는 로그인·CSRF 확인 후 본인의 위치만 앞으로 이동시키며, 아직 생성되지 않은 메시지 위치를 미리 읽음 처리할 수 없습니다. 읽음 처리는 메시지를 삭제하지 않습니다.

## 내 메뉴 순서

왼쪽 메뉴 아래 **메뉴 순서**를 누르면 각 메뉴 왼쪽 손잡이를 마우스나 터치로 끌어 옮길 수 있습니다. 키보드 사용자를 위한 위·아래 화살표도 제공합니다. **저장**하면 즉시 반영되며 같은 브라우저에서 계정별로 유지됩니다. 다른 기기에는 동기화되지 않습니다. **기본 순서로**를 누른 뒤 저장하면 초기 순서로 돌아갑니다. 닫기나 Esc로 닫으면 편집을 취소합니다. 휴대폰의 가로 메뉴에도 같은 순서를 적용합니다. 브라우저 저장 공간을 사용할 수 없으면 현재 창에서만 적용되며 안내 메시지를 표시합니다.

## 업무 요청 · 영업일 반복 · 상세 패널

**업무 → 업무 요청**의 구분은 업무·택배 발송·반복업무입니다. 운송장 칸은 택배 발송에서만 보이며, 수량 대신 담당자 옆에 실제 요청자를 표시합니다. 입고 메뉴의 수량 입력은 유지합니다.

반복업무는 선택한 시작일(오늘부터 1년 이내)부터 중지일까지 한국 시간 기준 영업일마다 별도 업무로 생성됩니다. 토·일요일, 한국 공휴일·대체공휴일을 제외합니다. 설과 추석은 한국 음력 변환으로 연휴 전체를 계산합니다. 알려진 선거일(2026-06-03, 2028-04-12)도 제외하며, 새 임시공휴일이나 회사 휴무일은 서버의 비밀값이 아닌 `MOA_HOLIDAYS`에 `2026-12-31,2027-01-04`처럼 추가할 수 있습니다. 미래에 새로 지정되는 휴무일은 자동으로 알 수 없으므로 반영이 필요합니다.

요청자·담당자와 일별 완료 기록을 보존합니다. 오늘 완료해도 다음 영업일 업무는 미완료로 새로 나타납니다. 앱의 상태 조회 시 서버가 지난 영업일의 누락된 건까지 중복 없이 생성하고, 열린 앱은 반복 요청이 있을 때 1분마다 확인합니다. 앱을 닫아 둔 동안에도 다음 접속 시 누락분을 생성합니다. 주말에 요청하면 다음 영업일부터 나타납니다. 공휴일에 새 업무를 생성하지 않으며, 이전 영업일에 끝내지 않은 업무는 유지됩니다.

**내 업무**, 오늘의 목록, 해야 할 일 알림에서 업무를 누르면 오른쪽 상세 패널이 열립니다. 요청자·담당자·운송장 정보를 확인하고 메모·체크리스트를 저장하거나 업무 수정을 열 수 있습니다. 체크리스트는 30개, 항목당 200자, 메모는 2,000자까지이며 해당 날짜의 업무에 저장되어 팀원과 공유됩니다. 다음 날 체크리스트와 완료 여부는 독립적입니다. 동시 수정 충돌은 저장을 거부하므로 입력을 복사한 뒤 최신 화면을 다시 열어야 합니다.

반복업무를 수정할 때 **이후 반복업무에도 적용**을 선택하면 제목·담당자·기본 메모를 다음 발생분에 반영합니다. 이미 생성된 과거 업무는 변경하지 않습니다. **반복 중지**는 상세 패널이나 **반복 요청 중** 목록에서 할 수 있으며 기존 기록과 당일 발생분은 유지합니다. 미래 시작 요청이나 휴일에 만들어 아직 발생분이 없는 요청도 목록에서 중지할 수 있습니다. 기존 DB는 데이터를 삭제하지 않고 새 테이블과 컬럼만 추가합니다.

### 상세 패널 자동 저장

메모·체크리스트는 입력을 멈춘 뒤 자동 저장하며, 닫기·Esc·업무 수정으로 패널을 닫을 때 마지막 변경까지 저장합니다. 느린 저장 중 추가한 입력은 순서대로 저장합니다. 저장 상태를 패널에 표시하고, 네트워크 오류 시 계정·업무별 초안을 같은 브라우저에 보관하여 다시 열 때 복구합니다. 다른 직원이 같은 내용을 수정했으면 자동 덮어쓰기를 멈추고 초안을 유지합니다. 브라우저 저장 공간도 사용할 수 없고 서버 저장도 실패하면 창을 유지하여 입력을 복사할 수 있게 합니다. 브라우저 탭 자체를 닫을 때 서버 저장은 보장할 수 없지만 입력 시 보관한 초안은 같은 브라우저에서 다시 열 때 복구합니다. 오늘의 업무·업무 목록은 제목 외에 메모·담당자·빈 영역을 눌러도 상세 패널을 열며, 완료 버튼은 독립적으로 동작합니다.

### 우선순위 · 요청일 · 마감일

업무 요청·수정에서 **보통 / 긴급**과 **요청일 / 마감일**을 선택합니다. 마감일은 요청일과 같거나 이후여야 합니다. 목록은 미완료 업무를 먼저, 그 안에서는 긴급 업무와 빠른 마감일 순으로 표시합니다. 목록과 상세 패널에 요청일·마감일·우선순위를 표시합니다.

**내 업무**의 담당자 본인 미완료 항목은 한국 시간의 달력 날짜 기준 마감 하루 전부터 빨간 느낌표와 **D-1**을 표시합니다. 당일에는 **오늘 마감**, 이후에는 **기한 지남**으로 바뀌며 완료하면 사라집니다. 해야 할 일 알림도 요청일 대신 마감일을 기준으로 판단합니다. 기존 업무는 보통으로 유지하고 기존 날짜를 요청일·마감일로 사용합니다.

반복업무는 우선순위와 요청일에서 마감일까지의 달력 일수 간격을 이후 발생분에 적용합니다. 예를 들어 시작일 10월 30일, 마감일 11월 2일이면 이후 생성되는 각 업무도 발생일에서 3일 뒤가 마감입니다. **이후 반복업무에도 적용**으로 우선순위·마감 간격을 변경할 수 있으며 이미 생성된 과거 기록은 바꾸지 않습니다.

### PC 백그라운드 채팅 알림

PC 화면 상단의 **PC 채팅 알림 켜기**를 누르고 브라우저 알림을 허용하면 다른 창을 보거나 Dayon을 최소화한 동안에도 보낸 사람과 메시지 미리보기를 시스템 알림으로 받습니다. 채팅 위젯의 버튼에서도 같은 설정을 바꿀 수 있습니다. 설정은 이 브라우저의 계정별로 유지됩니다. **PC 채팅 알림 켜짐**을 다시 누르면 끕니다. 브라우저가 차단 상태라면 주소창의 사이트 설정에서 알림을 허용해야 합니다.

채팅 위젯의 **알림 테스트**로 시스템 표시를 확인할 수 있습니다. OS의 알림 허용, 집중 모드·방해 금지, 브라우저 설정에 따라 실제 표시·소리·유지 시간은 달라집니다. 알림을 클릭하면 Dayon으로 돌아와 채팅을 엽니다. Service Worker 알림이 실패하면 지원되는 PC 브라우저의 Notification API로도 전달을 시도합니다.

읽지 않은 메시지는 권한 허용 여부와 관계없이 브라우저 탭 제목의 개수와 아이콘의 빨간 점에도 표시합니다. 채팅을 읽으면 해제하고, 본인이 보낸 메시지나 처음 접속하기 전의 기존 대화를 새 알림으로 다시 보내지 않습니다. 여러 탭의 시스템 알림 중복을 방지합니다.

Dayon 탭은 로그인한 상태로 열어 두어야 하며 인터넷 연결이 필요합니다. 탭·브라우저를 완전히 종료하거나 브라우저가 탭 실행을 중단한 동안의 서버 푸시는 제공하지 않습니다. 휴대폰의 백그라운드 수신은 보장하지 않으며 PC 상단 알림 버튼은 휴대폰 화면에서 숨깁니다. 휴대폰에서도 기존 앱 내 채팅·미확인 개수는 유지합니다.

## 사무실 재고 · 수입

**사무실 재고**는 기존 수입 일정과 별도의 수기 입력 공간입니다. 에센셜 20·24·28인치 각 4색, 메트론 20·24·26인치 각 4색, 카빈 20인치 7색, 파우치세트 단일상품으로 총 32개 옵션을 제공합니다. 상품·색상 검색 후 **수량 수정**에서 정상·반품·A/S·불량 수량을 각각 직접 입력하고 저장합니다. 초기값은 모두 0이며, 기존 수입 재고를 자동으로 옮기지 않습니다. 수량은 음수가 될 수 없고, 동시 수정 시 먼저 변경된 값을 덮어쓰지 않습니다.

반품·A/S·불량은 정상 재고와 분리합니다. 반품 양품화 후 정상 재고로 옮기거나 A/S 물품을 돌려보낸 뒤 수량을 줄이는 작업도 사용자가 직접 수정합니다. **업무 요청 → 사무실 입·출고**에서 상품 옵션·작업 구분·수량을 지정할 수 있으나 표시 정보일 뿐입니다. 업무 생성·완료·완료 취소·수정은 사무실 재고를 자동으로 더하거나 빼지 않습니다.

### 사무실 재고 변경 기록

사무실 재고 표 아래에서 ‘누가 어떤 상품 옵션의 어느 재고를 몇 개 늘리거나 줄였는지’를 확인합니다. 변경 시각(한국 시간)과 변경 전후 수량을 함께 표시하며, 한 번에 여러 재고 구분을 수정하면 바뀐 구분별로 기록합니다. 서버가 로그인한 처리자와 실제 저장 전후 수량으로 기록하므로 작성자·증감 수치를 화면에서 임의로 지정하지 않습니다.

택배 발송은 별도 사이드바 탭 없이 업무 메뉴와 공용 달력에서 관리합니다. 오늘 화면의 요약 카드는 오늘 할 일과 오늘 완료 두 개만 표시합니다.


## 일별 판매 · 취소/환불

**판매 · 취소/환불** 메뉴에서 한국 날짜(기본 오늘)와 사이트를 선택합니다. 판매 사이트는 **카페24·쿠팡윙·스마트스토어·지오코리아** 4개로 고정되며, 별도 사이트 추가 기능은 없습니다. 기존에 같은 이름으로 등록된 사이트의 ID와 일별 기록은 유지합니다. 그 외 이름의 과거 사이트 데이터는 DB에서 삭제하지 않습니다.

사무실 재고표와 동일한 32개 옵션을 **에센셜·카빈·파우치(단일)·메트론** 탭으로 나눠 표시합니다. 상품 탭을 바꿔도 미저장 입력을 유지하고 **전체 상품 저장**으로 선택 사이트의 32개 옵션을 함께 저장합니다. 표 내부 스크롤과 상단 저장 버튼으로 페이지 이동을 줄입니다. 수량(개) 기준이며 빈칸은 0으로 저장됩니다. 판매는 차감 전 수량, 취소·환불은 구분 없이 합산한 수량을 입력합니다. 기존 별도 취소·환불 기록도 합산하여 표시하고 저장하므로 재입력이 필요 없습니다.

**취소·환불률 = 취소·환불 수량 ÷ 판매 수량 × 100**입니다. 판매 100개 중 취소·환불 10개는 10%입니다. 옵션별·선택 상품별·선택 사이트 전체·각 사이트 및 전체 합계에 비율을 표시합니다. 전체 비율은 개별 비율의 평균이 아닌 전체 수량 기준이며 소수 첫째 자리까지 반올림합니다. 판매가 0이면 —로 표시합니다. 과거 주문의 취소·환불 처리로 비율이 100%를 넘을 수 있습니다. 사무실 재고와 수입 기록은 변경하지 않습니다.

날짜·사이트·상품 탭을 바꾸거나 앱 메뉴를 이동해도 저장 전 입력은 현재 창에 유지됩니다. 새로고침·창 종료 전에는 미저장 안내가 나오며, 로그아웃하면 초안을 비웁니다. 저장은 로그인한 팀원에게 공유되고 DB 재시작 후에도 유지됩니다. 같은 날짜·사이트를 다른 직원이 먼저 저장하면 덮어쓰지 않고 충돌을 안내합니다. **최신 기록 확인**은 미저장 입력을 유지하며, **입력 버리고 불러오기**는 확인 후 선택 날짜·사이트의 초안을 버립니다. 저장자와 최종 저장 시각을 표시합니다.

### 카페24 엑셀 가져오기

날짜와 판매 사이트를 선택한 뒤 **카페24 엑셀 가져오기**에서 `.xlsx` 파일을 바로 선택합니다. 첫 번째 시트의 첫 행을 헤더로 사용합니다. 기존 CSV 파일과 UTF-8(BOM 포함)·CP949/EUC-KR 인코딩도 지원합니다. 파일 크기는 2MB, 데이터는 최대 10,000행이며 엑셀은 최대 256열입니다. 엑셀 필수 열의 수식·오류 값은 거부하며 값으로 저장해야 합니다.

필수 열은 **주문상품명(옵션포함)·수량** 두 개뿐입니다. 옵션이 포함된 상품명에서 모델·인치·색상을 찾아 사무실 재고표의 32개 옵션에 연결하고 같은 옵션의 여러 행을 합산합니다. ‘비밀 링크’·‘스레드 전용’ 문구를 포함한 상품명도 처리하며 ‘메트론 카빈’은 카빈으로, 파우치는 단일상품으로 연결합니다. 불확실한 행은 미리보기에서 직접 옵션을 선택해야 반영할 수 있습니다. 음수·소수·빈 수량·중복 필수 열·열 개수 오류는 반영하지 않습니다.

엑셀은 브라우저에 포함된 SheetJS CE 0.20.3(Apache-2.0)으로 읽고 상품명·수량 열만 추출합니다. 결제금액·판매가·개인정보·취소·환불 등 다른 열은 집계에 사용하지 않습니다. 선택한 두 열 외의 데이터 값을 결과 객체에 보관하지 않으며, 원본 파일과 개인정보는 서버에 전송하거나 DB·브라우저 저장소·로그에 저장하지 않습니다. 브라우저에서 파일을 읽고 파싱한 뒤 원본 바이트 버퍼를 비웁니다. 미리보기는 상품명·수량·연결할 옵션만 표시하고 닫거나 로그아웃하면 비웁니다. 저장 요청에는 사무실 옵션 ID와 집계 수량만 포함되며 원본 상품명·파일명·주문·고객 정보는 포함되지 않습니다.

미리보기에서 대상 날짜·사이트, 원본 행 수, 연결한 옵션과 판매 수량 합계, 저장된 옵션 가격 기준 예상 매출을 확인합니다. 매출은 기존 옵션별 가격 × 수량으로 계산합니다(139,000원 × 2개 = 278,000원). **이 수량을 입력칸에 반영**하면 선택 날짜·사이트의 **판매 수량만** 옵션별 파일 합계로 교체합니다. 파일에 없는 옵션의 판매 수량은 0이며 같은 파일을 다시 가져와도 중복으로 더하지 않습니다. **기존 취소·환불 수량은 파일에 없는 옵션까지 모두 유지**하며 수기로 관리합니다. **전체 상품 저장**을 눌러야 서버에 반영됩니다. 기존 동시 수정 검사를 유지합니다.

## 총괄 · 공동관리자 · 운영자

사용자 화면의 **계정 · 보안 관리**에서 권한을 관리합니다. 총괄은 공동관리자·운영자 권한 부여, 계정 차단·해제, 해당 계정의 전체 기기 로그아웃을 할 수 있습니다. 공동관리자는 운영자 계정의 차단·해제·전체 로그아웃과 직원 초대를 할 수 있으며 다른 공동관리자나 총괄의 계정을 변경할 수 없습니다. 운영자는 기존 업무·판매·재고·문서·자료 기능을 사용하며 계정 관리와 직원 초대 권한은 없습니다. 총괄은 한 명으로 제한하고 자기 계정 변경 및 총괄 차단·권한 강등을 서버에서 금지합니다. 관리 작업은 처리자·대상·시각과 함께 기록합니다. 활성 계정과 대기 초대 정원은 4명이며 차단 계정의 기존 기록은 삭제하지 않습니다.

이번 마이그레이션은 이름 **이기정**과 로그인 아이디 **gijeong1312**가 모두 일치하는 기존 계정을 한 번만 총괄로 지정합니다. 이름만으로 권한을 부여하지 않으며 지정 완료 플래그가 있으면 재시작 시 재승격하지 않습니다. 새 설치의 최초 설정 키로 만든 첫 계정은 총괄입니다. 기존 users.role 값은 보존하고 별도의 account_access 테이블로 권한과 차단 상태를 관리합니다.

### 암호화 백업과 복원 검증

총괄만 **현재 로그인 비밀번호 재확인** 후 암호화 백업 다운로드와 보관 파일 복원 검증을 실행할 수 있습니다. 별도의 12~128자 백업 암호로 scrypt 키를 만들고 AES-256-GCM으로 암호화합니다. 계정 비밀번호 해시·권한·업무·반복업무·메시지·읽음 위치·재고·재고 로그·문서·자료실 원본·판매·관리 이력을 포함하며 로그인 세션과 대기 초대는 제외합니다. 백업 파일에는 민감한 회사 자료가 포함되므로 파일과 암호를 별도 안전한 장소에 보관해야 합니다. 서버는 백업 암호나 평문 백업을 보관하지 않습니다. 논리 백업의 원본 크기 한도는 48MB입니다.

백업 생성 및 보관 파일 검증 시 서버가 별도의 임시 SQLite DB를 만들고 모든 테이블을 실제 삽입·복원한 뒤 행 내용, 참조 무결성, DB 무결성, 메시지 순서 및 세션 제외를 검사합니다. 검증용 DB는 성공·실패와 관계없이 삭제하며 운영 DB의 업무자료를 덮어쓰지 않습니다. PostgreSQL 백업도 이 형식의 논리 데이터 복원을 확인하지만 PostgreSQL 자체의 시점 복원이나 제공자 백업 보존 정책을 검증한 것은 아닙니다. 운영 DB 직접 복원 API는 제공하지 않습니다.

총괄 마이그레이션 직후 최초 한 번은 실제 운영 스냅샷을 임시 암호로 암호화·복호화하고 별도 DB에 복원하여 검증하며, 성공 시 관리 이력과 완료 플래그를 남깁니다. 이 작업은 복원 가능성을 검사하는 것이며 영구 보관 백업을 만드는 작업은 아닙니다. 총괄은 별도로 백업 파일을 내려받아 보관해야 합니다. Render·Neon의 자동 백업·시점 복원 설정은 해당 서비스 연결 후 별도 확인해야 합니다.

## 공용 달력 · 일정 삭제

공용 달력의 구분 필터는 제거하고 모든 업무·사무실 입출고·발송·공통 일정·수입 일정을 함께 표시합니다. 날짜 칸 전체(빈 공간 포함)를 마우스·터치로 누르거나 키보드 Enter/Space로 선택하면 날짜별 관리 창이 열립니다. 그날의 일정을 추가·수정·삭제할 수 있습니다. 수입 일정은 인천 ETA와 창고 입고 날짜를 각각 별도 표시하며, 날짜가 같으면 두 구분을 모두 표시하되 날짜별 관리 창에서는 동일 일정을 한 번만 표시합니다. 표 보기에도 두 날짜를 각각 표시합니다.

업무 상세·일정 수정 화면에도 **일정 · 업무 삭제** 버튼을 제공합니다. 삭제 전 확인하고 로그인·CSRF·버전 검사를 적용하며 관리자 작업 이력에 처리자와 삭제 정보를 남깁니다. 다른 사용자가 먼저 수정한 기록은 최신 버전을 확인하기 전 삭제하지 않습니다. 완료한 수입 일정 삭제 시 기존 수입 누적 수량에서 제외되며 사무실 재고를 자동 변경하지 않습니다. 반복업무 삭제는 선택한 날짜의 발생 건만 삭제하고 이후 반복은 유지합니다. 운영 DB 복원 없이 삭제를 취소하는 기능은 없습니다.

## 메인 판매 · 환불 현황

오늘 메인 화면 상단에서 **어제·최근 7일 평균·최근 30일 평균**을 확인합니다. 한국 날짜 기준 어제까지의 카페24·쿠팡윙·스마트스토어·지오코리아에 저장된 판매·취소/환불 기록을 집계합니다. 판매 수량과 취소·환불 수량, 도넛 그래프로 취소·환불률을 표시하며 주간·월간 비율은 기간 전체 취소·환불 수량을 전체 판매 수량으로 나눈 가중 비율입니다. 오늘 입력과 해당 기간 밖의 기록은 제외합니다.

주간·월간 수량의 일평균은 입력된 날짜 수를 기준으로 계산하고 사용된 날짜 수 및 사이트 입력 건수(사이트×날짜)를 함께 표시합니다. 미입력을 0개 판매로 간주하지 않으며 일부 사이트만 입력된 날짜는 집계가 불완전할 수 있습니다. 수량이 모두 0이어도 명시적으로 저장한 기록은 입력일로 계산합니다. 판매가 없으면 비율은 —이며 과거 주문 처리로 환불률이 100%를 넘으면 그래프는 100%까지만 채우고 실제 비율을 숫자로 표시합니다. 해당 값은 판매 금액이 아닌 상품 수량 기반 현황입니다.

## 판매 탭 매출 · 옵션별 순위

판매 · 취소/환불 탭 상단에서 한국 날짜 기준 어제, 최근 7일, 최근 30일의 매출과 일평균을 표시합니다. 옵션별 판매 비중은 전체 판매 수량을 100%로 하는 원형 도넛 그래프로 표시하며 판매 수량으로 순위를 매깁니다. 예를 들어 전체 80개 중 한 옵션이 12개 팔리면 15%입니다. 원에는 모든 판매 옵션이 포함되고 목록은 상위 5개(동률 포함)를 먼저 표시하며 전체 보기로 펼칠 수 있습니다. 저장된 전체 사이트의 판매 수량에 고정 단가를 적용합니다. 에센셜 20/24/28인치는 99,000/119,000/139,000원, 카빈 20인치는 159,000원, 메트론 20/24/26인치는 99,000/119,000/134,000원, 파우치는 28,900원입니다. 색상에 따른 가격 차이는 없습니다.

각 기간의 순위는 색상까지 포함한 옵션별 매출 내림차순입니다. 동률은 공동 순위(1위, 1위, 3위), 판매 0개는 순위 없음으로 표시합니다. 7일·30일 평균은 기존 판매 현황처럼 입력된 날짜 수로 나누며 입력일·사이트 기록 수를 함께 표시합니다. 미입력 기록을 0으로 간주하지 않습니다. 취소·환불 처리 수량에 동일 단가를 적용한 차감액과 차감 후 금액도 별도 표시합니다. 할인·배송비·수수료·실제 과거 환불 결제가는 반영하지 않으므로 정산액이 아닌 고정 단가 기준 매출입니다. 저장 전 초안은 매출에 포함하지 않습니다.

### 공용 달력 업무별 색상

달력에서 날짜를 누른 뒤 각 업무의 **표시 색상**을 선택하면 즉시 저장되고 모든 직원에게 공유됩니다. 기본 색상과 파랑·초록·보라·분홍·주황·노랑·빨강·회색 중 선택할 수 있습니다. 업무·일정 등록 및 수정 화면의 **달력 표시 색상**에서도 설정합니다. 완료한 업무도 날짜별 목록에서 색상을 바꿀 수 있습니다. 반복업무는 생성 시 색상을 이어받으며 수정 화면의 이후 반복업무 적용을 선택하면 앞으로 생성되는 업무에도 적용합니다.

### 판매량 카드와 옵션 그래프

메인 화면의 **판매량**에는 판매 개수·취소/환불 개수·고정 옵션 가격 기준 매출(차감 전)을 표시합니다. 어제는 합계, 최근 7일·30일은 입력된 날의 일평균과 기간 합계를 표시합니다. 판매·취소/환불 화면의 도넛 바깥에는 모델·사이즈·색상으로 된 옵션 이름과 연결선을 표시합니다. 조각이나 이름에 마우스를 올리거나 키보드로 초점을 맞추면 판매 개수와 전체 대비 비율을 표시하고, 모바일은 눌러 확인합니다. 많은 옵션이 있어도 전부를 분모에 포함하며 작은 화면에서는 그래프를 가로로 스크롤할 수 있습니다.
