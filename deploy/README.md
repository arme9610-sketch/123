# DAYON 무료로 시작하기

**Render Free 웹 서버 + Neon Free PostgreSQL 데이터베이스 + Render 기본 주소**로 먼저 시험 운영하고, 필요할 때 유료 요금제로 바꾸는 구성을 준비했습니다. 업무 데이터는 별도 데이터베이스에 저장되므로 웹 서버의 임시 파일이 재배포 때 사라져도 기록을 유지할 수 있습니다.

아직 Render·Neon 계정은 연결하지 않았고 공개 접속 주소도 발급하지 않았습니다. 여기의 예제 파일을 저장하는 것만으로 가입, 배포, 결제는 이루어지지 않습니다. 두 서비스의 최신 무료 한도와 가입 조건은 생성 화면에서 확인해야 합니다. 이 환경에서는 Render 공식 사이트에 대한 네트워크 접근이 차단되어 서비스의 최신 요금·정책과 실제 배포 설정 유효성을 확인하지 못했습니다.

## 먼저 할 일

1. [Neon](https://neon.com/)과 [Render](https://render.com/)에 본인 계정으로 가입합니다. GitHub 로그인 방식이 제공되면 같은 GitHub 계정을 사용할 수 있습니다.
2. 각 서비스에서 **Free 요금제**를 선택하고 최종 화면에서 비용이 0인지 확인합니다. 유료 요금제나 기간이 정해진 유료 체험으로 바꾸지 않습니다. 무료 구성이 제공되지 않는다면 생성 전에 중단하고 다른 구성을 검토합니다.
3. Neon에서 데이터베이스를 만든 뒤 Render에서 GitHub 저장소 `arme9610-sketch/123`을 연결합니다.

비밀번호, 결제정보, 데이터베이스 접속 주소를 채팅에 붙여넣지 마세요. 접속 주소에는 데이터베이스 비밀번호가 들어 있으며 Render의 비밀 환경변수 입력란에 직접 저장합니다.

## 1. Neon 데이터베이스 만들기

- Free 프로젝트를 생성하고 데이터베이스와 사용자 계정을 준비합니다. Render 서버와 가까운 지역을 선택할 수 있으면 그렇게 합니다.
- 해당 프로젝트의 연결 설정에서 **pooled connection string**을 확인합니다. `postgresql://...` 형태이며 호스트, 사용자, 비밀번호, 데이터베이스 이름이 포함됩니다.
- 연결 주소를 아래 Render의 `DATABASE_URL`에 입력합니다. 이 주소를 GitHub 파일이나 화면 메모에 저장하지 않습니다.
- 공개 인터넷의 데이터베이스 연결은 TLS 인증서 검증을 사용합니다. 연결 문제를 해결하려고 인증서 검증을 끄지 않습니다.

DAYON 서버가 시작될 때 필요한 테이블을 준비합니다. 기존 회사 데이터와 섞이지 않도록 DAYON 전용 데이터베이스를 사용합니다. 이 개발 환경의 SQLite 기록은 자동으로 Neon에 복사되지 않습니다.

## 2. Render 웹 서비스 만들기

GitHub 저장소 루트를 사용하는 Node 웹 서비스를 생성합니다. Blueprint를 사용하는 경우 [render-free.yaml.example](render-free.yaml.example)을 참고할 수 있습니다. 이 파일은 **검토용 예제**이며 현재 Render 제공자 스키마로 검증되었다고 주장하지 않습니다.

| 설정 | 값 |
|---|---|
| 서비스 유형 | Node 웹 서비스 |
| 요금제 | **Free** |
| 서비스 이름 | `dayon-arme` 등 사용 가능한 이름 |
| Node 버전 | `24` |
| 빌드 명령 | `npm ci && npm run check` |
| 시작 명령 | `npm start` |
| 상태 확인 경로 | `/api/status` |

서비스 이름은 제안값입니다. 실제 주소는 Render가 발급한 주소를 사용하며, `dayon-arme`라는 이름이나 주소의 사용 가능 여부는 아직 확인하지 않았습니다. 별도 도메인 구매는 필요하지 않습니다.

Render의 환경변수 설정에 다음을 저장합니다.

| 변수 | 값 |
|---|---|
| `NODE_VERSION` | `24` |
| `NODE_ENV` | `production` |
| `MOA_SECURE_COOKIE` | `1` |
| `MOA_REQUIRE_DATABASE_URL` | `1` |
| `DATABASE_URL` | Neon에서 확인한 비밀 PostgreSQL 연결 주소 |
| `MOA_SETUP_TOKEN` | 첫 관리자 설정에 사용할 충분히 긴 무작위 비밀값 |

초기 설정 키는 서비스가 제공하는 비밀값 생성 기능을 사용합니다. Blueprint 예제의 `generateValue: true`도 배포 서비스에 키 생성을 요청합니다. 외부 데이터베이스가 아직 초기화되지 않았다면 `MOA_SETUP_TOKEN`이 없을 때 DAYON은 시작하지 않습니다. 웹 서버를 다시 만들더라도 동일한 Neon 데이터베이스에 연결하면 기존 사용자와 기록을 사용할 수 있습니다.

**`DATABASE_URL`이 비어 있으면 배포를 시작하지 마세요.** 무료 예제의 `MOA_REQUIRE_DATABASE_URL=1`은 접속 주소가 없을 때 시작을 거부하여 임시 SQLite로 전환되는 일을 막습니다. 무료 웹 서버 내부의 SQLite 파일에 실제 업무를 저장하면 재배포 때 기록이 사라질 수 있습니다. 이 무료 구성은 영구 디스크를 생성하지 않습니다.

웹 서버는 하나만 사용합니다. HTTPS 프록시는 공개 주소의 `Host`를 보존하고 SSE 응답을 버퍼링하지 않아야 합니다. CSRF 검사를 끄거나 임의의 전달 헤더를 신뢰하는 설정을 추가하지 않습니다.

## 3. 첫 관리자와 직원 계정 만들기

1. Render가 발급한 실제 HTTPS 주소로 접속합니다.
2. 본인이 Render 비밀 설정에서 확인한 초기 설정 키, 원하는 이름·아이디·10자 이상의 비밀번호로 관리자 계정을 생성합니다.
3. **팀 관리 → 직원 초대**에서 나머지 직원의 계정을 초대합니다.
4. 초대 링크를 직원에게 직접 전달하면 각 직원이 자신의 비밀번호를 정할 수 있습니다.

로그인한 직원 모두가 공용 업무, 일정, 발송 정보와 채팅을 볼 수 있습니다. 배포 서비스의 계정과 DAYON 직원 계정은 서로 다릅니다.

## 무료 시험 운영에서 확인할 점

- 서비스에 따라 사용하지 않는 서버나 데이터베이스가 쉬었다가 켜질 수 있어 첫 접속이 느릴 수 있습니다.
- 서버 실행 시간, 데이터 용량, 연결 수, 전송량 등의 무료 한도가 있습니다. 최신 한도는 각 서비스 화면에서 확인해야 하며 여기서는 특정 수치를 보장하지 않습니다.
- 웹 서버가 재시작하거나 대기 상태가 되면 실시간 연결이 끊어질 수 있습니다. DAYON은 재연결을 시도하고 최신 데이터를 다시 읽습니다.
- 무료 데이터베이스는 웹 서버 재배포와 별개로 데이터를 저장하지만, 데이터베이스 자체를 삭제하거나 제공자의 보존 조건을 넘기면 데이터가 보장되지 않습니다.
- 이 앱에서 외부 데이터베이스를 자동 백업하지는 않습니다. 운영 시작 전에 Neon의 백업·내보내기·복원 범위와 보존 기간을 확인하고 필요한 별도 백업을 마련합니다.
- 비용 상한·유료 전환·자동 과금 설정이 있다면 무료 운영 의도에 맞게 확인합니다. 앱이 자동으로 요금제를 올리지는 않습니다.

무료 한도를 넘으면 앱이 느려지거나 접속이 중단될 수 있으므로 먼저 작은 범위로 시험 운영합니다. 중요한 실제 업무 기록을 유일한 사본으로 보관하기 전에 복원 가능한 백업을 확인하세요.

## 배포 후 검증

- HTTPS로 관리자 생성·로그인·로그아웃이 되는지 확인합니다.
- 서로 다른 직원 계정으로 일정 등록과 채팅이 공유되는지 확인합니다.
- 입고 완료 및 완료 취소 시 두 직원 화면의 수량이 함께 변하는지 확인합니다.
- 테스트 업무를 등록한 뒤 Render 서비스를 재시작하거나 재배포해도 기록과 로그인이 유지되는지 확인합니다.
- 서버가 쉬었다가 다시 켜질 때 로그인과 채팅 재연결이 정상 동작하는지 확인합니다.
- Neon 데이터 내보내기와 복원 방법을 확인합니다.

현재 공개 서비스에서는 위 검증을 실행하지 않았습니다. 로컬 테스트와 실제 계정에서의 배포 검증은 별개입니다.

## 마음에 들면 유료로 전환하기

Render 웹 서버를 유료 요금제로 올리면서 **같은 Neon 데이터베이스와 환경변수**를 유지하면 데이터 이동 없이 운영을 이어갈 수 있습니다. Neon의 저장 용량이나 사용량이 부족하면 해당 프로젝트의 요금제를 별도로 검토할 수 있습니다. 두 서비스의 비용은 각각 발생하므로 변경 화면에서 금액을 확인한 뒤 진행합니다.

기존 [render.yaml.example](render.yaml.example)은 **유료 서버와 영구 디스크에 SQLite를 두는 별도 대안**입니다. 무료 구성의 단순 요금제 변경과는 다릅니다. PostgreSQL에서 SQLite로 바꾸거나 다른 데이터베이스로 옮기는 경우에는 먼저 원본의 내보내기·백업을 보존하고, 새 DB에 복원·이전한 후 실제 레코드와 로그인 동작을 확인해야 합니다. 원본을 삭제하는 방식으로 이전하지 않습니다. 해당 예제를 무료 배포에 사용하지 마세요.
